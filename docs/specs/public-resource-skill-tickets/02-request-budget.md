## What to build

在搜索繁忙、上游限流或部分不可用时，用户仍获得有明确状态的结果或错误，且一次检索不会无限发起上游请求。

## Acceptance criteria

- [ ] 明确并实现单次总时限、上游调用数、重试数及并发上限；参数可说明且有边界测试。
- [ ] 实现短时缓存及相同查询请求合并，记录缓存期限；完整/部分/失败分别处理，不将故障或不完整结果伪装为完整命中。
- [ ] 取消与超时贯穿多次请求；取消后不再重试，不将运行标为成功。
- [ ] 从会话到结果卡验证限流、超时、空结果与部分成功，保留真实状态且不暴露内部服务或凭证。
- [ ] 不调用付费检索兜底；留下耗时、调用量和失败类型等必要诊断，不记录敏感全文。
